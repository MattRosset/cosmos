## Judgment calls

### JC-1 — D5 spec/code contradiction (rule 1): ErrorGateApp cannot keep `: OctreeSource`
**Context.** D5 says re-type `packs.ts:41` to `readonly octreeCombined?: CombinedOctreeSource`
AND "leave `ErrorGateApp.tsx:94`'s explicit `: OctreeSource` local annotation … it never feeds
the pick." But `ErrorGateApp.tsx:94-99` assigns that `OctreeSource`-typed local INTO the
`sources.octreeCombined` field. If the field becomes `CombinedOctreeSource?`, an `OctreeSource`
value (lacking `prefixRangesFor`) is no longer assignable → typecheck error. `injectOctreeFault`
(`ErrorGateApp.tsx:45`) also returns a bare `OctreeSource`. The two D5 statements are mutually
inconsistent; verified by reading the live code, not the spec.
**Decision.** This is a real spec bug, not a frozen-interface thaw (packs.ts + ErrorGateApp are
app glue, not on the frozen list). Resolved minimally + correctly (rule 1 = update the spec, do
not improvise around): re-type the field as D5 intends, and make ErrorGate keep producing a
`CombinedOctreeSource` — type the local `CombinedOctreeSource`, and change `injectOctreeFault`
to preserve the combined type by spreading the source (`{ ...source, loadTile }`), which carries
`prefixRangesFor`/`getNode` through and only overrides `loadTile`. ErrorGate still never feeds
the pick (it wires no `octreeCombined`/`gaiaIds` prop to StarScene). Spec D5 updated to record
this.

### JC-2 — Extracted `gaiaHitWins` (cross-source arbitration) instead of inlining it
**Context.** Gate 4 (additivity) is a blocking deterministic check, but the "farther gaia loses /
nearer gaia wins" comparison originally lived inline in `StarScene.pickAt` — a WebGL closure
vitest can't reach here. Testing it by re-deriving the `<`-comparison in the test would violate
CLAUDE.md rule 1 (query real state, don't re-derive).
**Decision.** Extracted the arbitration to a pure exported `gaiaHitWins(gaiaHit, starAngleRad)`
in `octree-pick.ts`; StarScene calls it. Gate 4 tests the SAME function production runs. Trivial
2-line predicate, but the extraction is what makes the additive contract a real gate rather than
a re-derivation.

### JC-3 — Extracted `selectWithGaiaUpgrade` + `SelectionPort` for the staleness guard
**Context.** Gate 3 requires asserting the staleness guard (a slow resolve of an old click must
not clobber a newer selection). That logic sat in a StarScene closure reading `useSelectionStore`
directly — untestable without WebGL/React, and re-deriving it in the test would again break rule
1.
**Decision.** Extracted the select + async upgrade into `glue/gaia-identity.ts` behind a
`SelectionPort` (`select` / `getSelectedId`). StarScene injects a port wrapping `useSelectionStore`;
the test injects an in-memory port + a manually-settled resolver to drive the race
deterministically. The unit test exercises the real production function.

### JC-4 — Visible-mount filter for the pick holder = `kind === 'octree' && seen === tick`
**Context.** Failure mode "Hidden/stale mounts" says only currently-visible mounts are pickable,
and to log the chosen filter if distinguishing visible from merely-tracked is fiddly.
**Decision.** Used `seen === tick` (the frame's own visibility mark, set at `GalaxyScene.tsx:579`
for cut mounts; the trailing pass hides `seen !== tick`) intersected with `kind === 'octree'`
(procgen excluded — synthetic, no real catalogIds). This is exactly the drawn set that frame. The
holder is republished only when this set changes vs. last frame (identity + length compare over a
reused scratch), so an unchanged frame allocates nothing — mirrors the feeds' low-frequency-write
discipline. Cleared to `null` on GalaxyScene unmount and whenever the visible set empties.

### JC-5 — Gate 5 e2e: exact-id assertion + BUG-6 real-run folded in; reference-only from the start
**Context.** Gate 5 allows a presence-only sweep but PREFERS asserting the exact `gaia:<source_id>`
"if feasible via `projectToScreen` on a mounted gaia star … if it requires a new test hook, add
one". The "Verification beyond the gate" section separately wants a real-run smoke that a click
yields a 19-digit id (BUG-6 class, which fetch mocks can't catch).
**Decision.** The exact-id assertion was feasible WITHOUT a new hook: the CLAIM-1-flip sweep
already yields a concrete gaia pixel, so the spec clicks it and asserts `selectedId` matches
`/^gaia:\d{19}$/` after the async upgrade — folding the real-run smoke into the same spec (no
separate manual step needed). Kept reference-only (`test.skip(!!process.env.CI, …)`) from the
outset per the local-e2e-vs-CI convention: tile-mount timing is machine-dependent and the
blocking contract is gates 2–4. No new test hook added.
