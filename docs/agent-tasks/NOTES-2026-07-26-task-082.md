## Judgment calls

**JC-1 — D4 is impossible in this workspace; the pixel proof moved to e2e.**
D4 requires `WebGLRenderTarget` + `readRenderTargetPixels` inside vitest. Measured with a
throwaway probe test: this workspace's vitest env is jsdom with neither the `canvas` package
nor `headless-gl`, so `HTMLCanvasElement.prototype.getContext` throws "Not implemented" and
`THREE.WebGLRenderer` cannot be constructed. No test in the repo has ever used a
`WebGLRenderer`. The spec says to stop and report rather than fall back to uniform
assertions — reported to the user, who was asked to choose between an e2e gate, adding
`headless-gl`, and marking the task blocked; no answer came, so the default was taken:
**the pixel proof lives in `e2e/tests/universe-impostor-scale.spec.ts`**, exactly as the
sibling TASK-085 resolved the same problem one day earlier
(`e2e/tests/universe-overlay-scale.spec.ts`). The unit tests in
`packages/render-galaxy/test/impostor.test.ts` are STRUCTURAL backups and say so in a comment.
D4's intent — a pixel assertion that fails against the pre-change module — is met; its
literal mechanism is not. *Candidate triage: spec/task bug (the spec assumed a capability
the repo does not have).*

**JC-2 — the ablation is a new dev hook, not an absolute pixel threshold.**
An e2e gate could have asserted `litFrac > 0.006` at the universe vantage (pre-change:
0.005455, post-change: 0.006584 — the threshold does separate them). Rejected: that number
encodes this machine's win32 SwiftShader build, and CI is linux SwiftShader, so it is exactly
the "CI-only failure" / "vacuous pass" trap. Instead added
`__cosmosDev.setImpostorRadiusPc(pc | null)` (holder `impostorRadiusOverride` in
`GalaxyScene.tsx`, wired in `StarApp` and `M4aApp`), so the gate ablates the impostor *inside
one run* and asserts a **frame delta**. Costs one `??` per frame. Precedent:
`__cosmosDev.setTier` already mutates render state for e2e.

**JC-3 — uniform named `uPcToUnits`, and applied once at the projection, not twice.**
D1's GLSL multiplies `uContextScale` into the offset and the radius separately. The merged
TASK-081/085 pattern (`galaxy.vert`, `stars.vert`, `nebula.vert`, `lineset.vert` — 4 of 4
siblings) instead names the uniform `uPcToUnits` and applies it once:
`gl_Position = projectionMatrix * vec4(viewPos * uPcToUnits, 1.0)`. Algebraically identical
(both terms are parsecs), one multiply cheaper, and it keeps the structural test convention
(`* uPcToUnits, 1.0)`) uniform across the four renderers. The spec's **Frozen Interface** is
the TS surface (`setRadiusPc`, `setContextScale`) and that is honoured exactly; only the
private uniform name deviates. *Candidate triage: doctrine gap — a spec that pins GLSL text
while also saying "mirror what TASK-081 shipped" can contradict itself.*

**JC-4 — the context scale is KEPT even though it is measured visually inert.**
The spec's OPEN section says: measure whether the radius multiply alone is already
context-invariant, and if so **drop D1 and the `× pcToUnits`**. Measured (see below): it is
invariant — bit-identical frames — at the only settled universe vantage that exists. The
uniform was kept anyway, so this is a deliberate deviation from that instruction and the
reason must stand on its own:

- Uniform scaling is invariant in the **perspective divide**, which is what the measurement
  covers, but not in **depth**. `camera.far = 1e6` (`StarScene.tsx:30`), in active-context
  units. With the scale, the billboard sits at `z ≈ 0.18` units at the 0.18 Mpc vantage
  (margin ~5.5e6×). Without it, `viewPos` stays in parsecs: `z ≈ 1.8e5` (margin 5.5×) at
  0.18 Mpc, `6e5` at 0.6 Mpc (margin 1.67×), and **clipped entirely past 1 Mpc**. That is
  arithmetic over two measured constants, not the falsified assumption the OPEN section
  warns about (which was about *angular size*).
- It keeps the impostor consistent with the 4 sibling renderers, all of which take a context
  scale; an impostor that alone kept a parsec `viewPos` would be the next reader's trap.

**This is the one place where the executor overrode a written instruction.** If the reviewer
disagrees, deleting the uniform is a ~6-line change and no pixel moves today.
*Candidate triage: spec/task bug — the OPEN branch contradicts the spec's own Frozen
Interface, which mandates `setContextScale`; a branch that cannot be taken without breaking
another clause should have been resolved before hand-off.*

**JC-5 — `milkyWayRadiusPc` kept on the props, dropped from the internals.**
D4 says the prop stays on `GalaxySceneProps` and all 7 call sites. It does, still required,
now documented as vestigial. But nothing inside the component reads it any more, so the
destructure, the `makeProcgenMount` parameter, its argument, and its `useEffect` dep were
removed — an unused destructured prop is a lint error, and threading a value nothing uses
would re-create the "apparent source of truth" this task is deleting.

## Measurements (all at the settled 0.18 Mpc universe vantage, tier pinned high, win32 SwiftShader)

| variant | litFrac | meanLuma |
| --- | --- | --- |
| shipped (radius = `discRadiusPc` 15,000 pc, context scale on) | 0.006584 | 3.7490 |
| impostor ablated (radius pinned 0) | 0.005455 | 3.7016 |
| radius 30,000 pc (2×) | 0.016875 | 3.9416 |
| **no context scale at all** (`uPcToUnits` pinned to 1) | **0.006584** | **3.7490** |
| pre-change module (radius multiply reverted) | 0.005455 | 3.7016 |

Three things to read off this table:

1. **The fix works.** The impostor now contributes 0.001130 of the frame (+21% litFrac) and
   grows with the radius. Pre-change it contributed **exactly 0.000000** — its litFrac equals
   the ablated figure to the last digit, which is the cleanest possible confirmation of
   `galaxy-impostor-scale-is-inert.md`.
2. **The OPEN question answers "inert".** No-context-scale is bit-identical to
   with-context-scale. That is TASK-085's uniform-scaling invariance confirmed a third time
   (and a third defect where the "obvious" 1e6× visual error was not the cause).
3. **The gate can be self-relative**, hence JC-2.

## Findings to report (no code change here)

1. **D4's T2 is unrunnable in the app, on the spec's own facts.** T2 wants the same physical
   galaxy to render to the same lit-pixel count from `galaxy` and from `universe`. Per F7 the
   impostor's opacity is provably **0** in galaxy context at any canvas ≥ 493 px (the e2e
   viewport is 720), so the galaxy-context count is 0 by construction and the comparison is
   vacuous. In an offscreen harness (which does not exist here) it would have worked. T3 is
   covered instead by the existing galaxy-context screenshot baselines not moving.
2. **`m1-betelgeuse` is red, and it is not this task's doing** — same finding as TASK-085's
   note 6. Measured: 67,414 differing pixels on this branch vs the 67,415 / 67,394 / 67,415
   that TASK-085 recorded across applied/stashed/unchanged trees. Inside that ±21 run-to-run
   band, so the drift is pre-existing. Not re-recorded. Screenshots are reference-machine-only
   and non-gating on CI.
3. **No universe-context screenshot baseline moved.** Gate 3 predicted they would. `m3` (the
   only screenshot spec that traverses universe) passed unchanged, along with `m2`,
   `ctxswitch`, `flythrough`, `perception-cards`, `perception-scale`. Nothing was
   re-recorded. Consistent with finding 5: the impostor's share at the reachable vantage is
   small.
4. **`flythrough3`'s wall-clock clauses fail on this machine on BOTH trees.** With the change:
   p95 51.1 ms, then 98.5 ms on a rerun. With the change stashed and rebuilt: p95 39.5 ms but

   **deterministic** figures were identical across trees (`pts=1113495 draws=10 chunks=10`),
   so the diff moves no work budget. A real fill-cost question remains open and is NOT
   answered here: the impostor is now a large additive sprite that previously drew nothing,
   and per `docs/research/` BUG-4 the universe GPU-fill cliff is invisible on a fast discrete
   GPU. Wants a GPU timer query or an integrated-GPU run, not an FPS number.
5. **The "pronounced before/after" the spec predicts does not materialise at the vantage the
   app can actually reach.** F8's 84% impostor share is at 0.6 Mpc; the ascent lands at
   **0.18 Mpc**, where the measured contribution is a faint halo (+21% of lit pixels, +1.3%
   mean luma) and the two frames are near-indistinguishable by eye. Both read as a small
   bounded spiral. For TASK-080's Decision 2 the honest answer is: the universe view already
   reads as a bounded object at 0.18 Mpc (that was TASK-085's fix), and this task makes it
