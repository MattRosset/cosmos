# NOTES — TASK-072 (integrated-GPU boot tier + pixel-ratio cap)

Judgment calls logged as they were made, per `CLAUDE.md`. Triage each after merge into
exactly one of: spec/task bug · executor bug · doctrine gap.

## Judgment calls

1. **New module `packages/scene-host/src/gpu-detect.ts`** rather than adding
   `classifyRenderer`/`detectInitialTier` into `quality.ts`. Not stated by the spec.
   `quality.ts` is pure tier-state-machine logic with no DOM access; `gpu-detect.ts`
   is the only file that touches `document`/`WebGLRenderingContext`. Keeping the DOM-
   touching code isolated makes `quality.ts` trivially testable in the existing
   fake-timers style and keeps the new file's surface small (matches "keep it dumb
   and testable" from the spec).

2. **`computeEffectivePixelRatio(tier, dpr, resolutionScale)` lives in `quality.ts`,
   exported, and `SceneHost.tsx`'s `QualityApplier` calls it.** The spec described the
   formula but not where the pure function should live. `QualitySettings.tier` is
   already on the object `QualityApplier` receives, so no new plumbing was needed.

3. **`detectInitialTier()` is called once via `useMemo(() => detectInitialTier(), [])`
   in `StarApp.tsx`**, not inline as a JSX prop expression. Inline would re-invoke (and
   re-log) on every StarApp render, even though `SceneHost`'s lazy `useRef` only reads
   the prop once. `useMemo` with an empty dep array matches the existing
   `isWebGL2Available()` probe one line above it.

4. **Boot log uses `console.info('[cosmos] boot GPU tier: renderer=... tier=...')`.**
   The spec said "existing diagnostics path" but the only existing structured sink
   (`@cosmos/diagnostics` `reportError`) is for `AppError`s (loader/streaming/worker/
   render/persistence/invariant/unknown kinds) reported via `toAppError` — a
   successful boot-tier choice isn't an error and forcing it through that sink would
   misuse `AppErrorKind`. Followed the repo's existing plain-`console` `[cosmos...]`
   prefix convention instead (`report-error.ts:59`, `ErrorBoundary.tsx:38`,
   `SystemScene.tsx:98`). The line always fires (both success and every failure
   branch), satisfying "diagnosable from logs alone" even when the log content is
   `renderer=unknown tier=high`.

5. **`detectInitialTier`'s try/catch always logs one line, in both the success and
   failure paths**, rather than only on success. Spec's "any exception ⇒ high" reads
   as the failure-mode contract; logging on the failure path too costs one line and
   removes an otherwise-silent branch, which the spec's own "diagnosable from logs
   alone" framing wants un-silent.
