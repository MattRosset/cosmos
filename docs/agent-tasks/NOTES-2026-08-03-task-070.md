# NOTES — TASK-070 (search Gaia by DR3 source_id + fly to it)

Judgment calls logged as they happened (CLAUDE.md §Judgment calls). Triage each after merge into
spec-bug / executor-bug / doctrine-gap.

## Judgment calls

1. **Index-access path shipped: HTTP Range with a full-fetch fallback.** Spec left this open
   ("record which path shipped"). `loadGaiaReverseLookup` probes `Range: bytes=0-15`; a 206 →
   range-mode binary search (~log2(N) 16-byte reads, never fetches the 74 MB index whole); a 200
   (no range support — the `file://` test fetch, some servers) → one full fetch + in-buffer search.
   Verified: vite preview serves 206 for the dense pack; the CI/sample path via fileFetch uses the
   200 fallback. Both covered by unit tests.

2. **`tileId` = index into `manifest.tiles` (on-disk BFS order).** The spec's record is
   `(source_id, tileId, indexInTile)` but did not fix what `tileId` denotes. Chose the tiles-array
   index because it is a natural stable u32 and the runtime maps it back with one `manifest.tiles[tileId]`
   lookup. Determinism gate keeps the tile order byte-stable.

3. **Reverse lookup is self-contained (fetches manifest.json + `decodeTile` directly), not via
   `loadOctreePack`.** Avoids a second manifest fetch and needs no new method on the shared
   `OctreeSource` interface. Still reads the plain on-disk gaia octree (Step 0), never `octreeCombined`.

4. **`onGoToPosition` is OPTIONAL on `SearchPaletteProps`.** Keeps the named-star tests and any
   named-only host byte-identical (Frozen Interface). A gaia hit is inert without it; the real host
   always provides it. `resolveGaiaId?` likewise optional-injected (mirrors 087/088/089).

5. **Added `test-hook.flightTarget`** (live getter off `jumpDistancePcHolder.target`) so the e2e can
   assert the fly target deterministically (set synchronously by `flyTo`), instead of waiting on
   animation/pixels. This is the guard against the "flew via onGoTo(bodyId) = silent no-op" trap.

6. **Gaia miss renders the same "No matches" empty state** as a named-star miss (same class/text) —
   one empty state, not a distinct "gaia not found" string (out of scope; spec says "normal empty state").

7. **BEYOND SPEC — `build:gaia-index` + `writeSourceIdIndexFromPack`.** The user hit the recurrent
   gap that a pack built before this task has no index → search degrades to "No matches" (their local
   dense `octree-gaia` behind `.env.local`). Added a tool that derives the index from an existing
   pack's tiles+sidecar (no snapshot rebuild); output is byte-identical to the build path (unit-tested).
   The reverse lookup already degrades gracefully (404 → null) so a stale pack never crashes.

8. **pack-octree coverage: excluded the 3 CLI entry files, ratcheted threshold 80 → 90.** The CLIs
   (`cli.ts`, `gaia-cli.ts`, `gaia-index-cli.ts`) are thin argv wrappers around tested functions and
   run top-level on import; excluding them scopes the gate to logic. Real logic coverage is ~96.6%, so
   the threshold went UP, not down (honors the "ratchet up, never down" note). Not a threshold-relax to
   force a pass — the logic (`writeSourceIdIndex`, `writeSourceIdIndexFromPack`, `buildGaiaPack`) is 95%+.
