## J2 — a fourth nav unit test, beyond the three the spec listed

Deliverable 2 specified three tests. Added a fourth: **"booted-in-galaxy WITHOUT an anchor
still never exits"**. The spec's own F2 control test covers the no-anchor case, but it builds
its controller *differently* (no tree anchor, camera at `[0.1,0,0]`, never placed past the
gate). The disjunction `ownGalaxyContext || galAnch !== null` is only safe if the no-anchor
path stays closed **with the camera actually placed past the exit gate**, which no existing
test does. Cheap, and it is the assertion that would catch a future "simplification" of the
condition to `galAnch !== null || true`-shaped nonsense.

**Test power verified, not assumed.** Reverted `controller.ts` and re-ran: exactly one of the
four fails (`booted-in-galaxy WITH an anchor exits past the gate`), the other three pass in
both states by design — they are guards against over-reach, not proofs of the fix. Recorded
here so a reviewer does not read "3 of 4 pass unchanged" as dead tests.

## J3 — widening the shared `__cosmos` e2e type in `m1.spec.ts` (outside the Deliverables list)

Deliverable 5 step 8 requires `expect(__cosmos.errorCounts.total).toBe(0)`, but the e2e
`Window.__cosmos` declaration did not include `errorCounts`, so the spec did not compile.

`m1.spec.ts` is the **single** home for that type — every other spec (`m3`, `m4a`,
`ctxswitch`, `flythrough3`) declares only its own probe globals, and `error-gate.spec.ts`
reads `errorCounts` off its own probe result object, not off `window.__cosmos`. The file's
own comment records two prior widenings for exactly this reason (TASK-029, TASK-040), so
adding a third optional field follows the established precedent rather than inventing a
pattern. Added `errorCounts?: { total: number; streaming: number }` and extended that
comment. No behavioural change; `pnpm verify` and every existing spec unaffected.

Flagging it because it is a file edit outside the task's Deliverables list.
