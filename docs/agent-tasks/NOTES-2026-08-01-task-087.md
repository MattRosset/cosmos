## Judgment calls

- **JC-1 — export `resolveRelativeUrl` from octree.ts.** Step 0c mandates reusing it, but it
  is module-private. Chose to add the `export` keyword (additive; NOT added to the package
  `index.ts` public surface — imported intra-package by `gaia-sourceids.ts`). Alternative
  (duplicate the 8-line helper) rejected: the spec says "reuse", and duplication drifts.

- **JC-2 — existing test `'single source is a pass-through'` (octree-combined.test.ts:263)
  asserts `combineOctreeSources([shallow]).toBe(shallow)`.** The spec (Frozen interface +
  D2) explicitly REQUIRES wrapping the single-source return in a `CombinedOctreeSource` so
  Task B never receives a bare `OctreeSource` lacking `prefixRangesFor`. That directly
  contradicts the `.toBe(shallow)` identity assertion. This is spec-mandated, not a test
  weakening: updated the test to assert (a) it is NOT the bare source, (b) it delegates
  `getNode`/`loadTile` faithfully, and (c) `prefixRangesFor` returns one full-width range
  with the source prefix. Logged per CLAUDE.md rule 1 (contradiction → the spec already
  resolved it in D2's favor).

- **JC-4 — `ErrorGateApp.tsx:92` `let octreeCombined` needed an explicit `: OctreeSource`
  annotation.** Widening `combineOctreeSources`' return to `CombinedOctreeSource` made the
  `let` infer that subtype, then line 93 reassigns it with `injectOctreeFault(...)` which
  returns a bare `OctreeSource` → TS2741. Annotated the `let` as the base `OctreeSource`
  (consistent with the spec's rule that the app keeps it typed `OctreeSource`; only Task B
  re-types to reach `prefixRangesFor`). Backward-compatible, no behavior change. The other
  four apps (M4a/Soak4/Flythrough4/Star) use `const octreeCombined = ...` with no reassign,
  so they type-check unchanged.

- **JC-3 — single-source wrapper range for a count-0 tile.** Spec says "one full-width range
  (or [] for a not-yet-loaded key)". For a *loaded* tile with count 0 I return `[]` (uniform
  with the count-0 rule in `concatBatches`: a zero-width range carries no provenance).
