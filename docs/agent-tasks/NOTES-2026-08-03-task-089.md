## Judgment calls

**JC-1 — D3 refactor shape.** Chose `pickAtDetailed(x, y): { id: BodyId | null; gaia: GaiaCardDetails | null }` as suggested in the spec. Made `pickAt = (x,y) => pickAtDetailed(x,y).id` so `__cosmos.pickAt` is byte-identical. The `gaia` payload in `pickAtDetailed` is only built when a gaia hit wins (fast path unchanged for all non-gaia clicks).

**JC-2 — D4 shape choice.** Chose option (a): `onUpgrade?(catalogId: number, sourceId: bigint) => void` callback added to `selectWithGaiaUpgrade`. Called inside the staleness guard, BEFORE the `selection.select(...)` call per spec ordering requirement. This keeps the guard's single source of truth in `gaia-identity.ts` and stays unit-testable.

**JC-3 — D6 Breadcrumb label.** Used `Gaia DR3` as the label for all `gaia:*` ids. It doesn't include the id digits (which would require parsing and formatting a potentially 19-digit number, plus a BigInt guard — disproportionate for a one-liner breadcrumb segment). The InfoPanel is the detailed surface.

**JC-4 — D5.2 match-check in getGaiaCard.** The match-check compares either: the parsed numeric tail against `holder.catalogId` (provisional `gaia:<catalogId>`) OR the parsed BigInt tail against `holder.sourceId` (upgraded `gaia:<source_id>`). Used a `try/catch` around `BigInt()` parse to guard non-numeric tails as specified (failure mode: BigInt corruption).

**JC-5 — `GaiaCardView` re-export.** Added to `packages/ui/src/index.ts` barrel alongside `BodyLookupAdapter`, so `Hud.tsx` can import it from `@cosmos/ui`.
